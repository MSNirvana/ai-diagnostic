# AI 咨询诊断系统 · 设计文档

- 日期：2026-06-11
- 状态：设计已确认，待进入实现计划

## 一、产品定位

一个 AI 驱动的企业管理诊断系统。核心不是"老板和 AI 对话"，而是一套**结构化诊断流水线**：老板按模块化问卷提交企业现状，系统按模块调用专家 skill 跑通（抓数据、内外对比、分析），最终在系统内分模块呈现"结论 + 证据 + 行动建议"，可下钻查看数据支撑。

与"裸聊 ChatGPT"的本质区别：每类问题背后挂一个**专家 skill**，它会真去抓数据、做实证分析，给的是"理论 + 数据证据 + 方案"，不是空谈理论。

**护城河 = skill（专家能力）本身。** skill 在服务端执行、绝不下发；老板可见内容只露"事实 + 结论"，藏住"方法 + 过程"。

## 二、顾问思维原则（系统设计基石）

站在顶级咨询顾问的角度，把五条思维纪律焊进系统，区分强制与可选：

**跨领域通用、强制（写进 skill 契约）：**
1. **MECE（不重不漏）**：模块切分相互独立、合起来覆盖企业全貌
2. **结论先行（金字塔原理）**：卡片表层先给结论（So-What），再给证据
3. **So-What 追问**：任何数据/分析都要回答"对老板意味着什么"
4. **行动导向**：诊断要落到"先动哪几件事"
5. **内外对比**：内部现状 vs 外部基准，问题才立得住

**领域相关、可选（由 skill 自声明）：**
- **假设驱动**：降级为某些 skill 的方法选项之一，不强制（不同领域专家工作法不同）

## 三、系统架构

四段式诊断流水线 + 支撑它的 skill 库：

```
[1. 问卷输入层] → [2. 分诊编排中枢] → [3. Skill 执行层] → [4. 结构化结果层]
                                            ↑
                                    [ Skill 库 + 标准规范 ]
```

**1. 问卷输入层**
- 按 MECE 切分的模块化问卷，老板按模块填现状/问题，可只填部分模块
- 填写本身即"分诊"——填了哪些模块，就触发哪些 skill

**2. 分诊编排中枢（核心）**
- 读问卷，确定跑哪些模块的 skill、按什么顺序
- 给每个 skill 准备输入（问卷内容 + 内部数据）
- 协调并行/串行执行，汇总结果
- 平台的"大脑"，未来 skill 工厂（自动生成）挂在这层之上
- **中枢只定契约，方法交给每个 skill 自己声明**

**3. Skill 执行层**
- 每个 skill = 一个领域专家，遵循统一契约
- 工作方法由 skill 自声明（假设驱动 / 指标体检 / 框架扫描 / 流程建模…）
- 第一版手工造样板 skill 定义标准；后续靠案例迭代加深；远期靠自动生成扩充

**4. 结构化结果层**
- 不输出文档，输出分模块卡片（详见第六节）

**Skill 库 + 标准规范**
- 所有 skill 遵循同一格式，规范定义"合格 skill 长什么样"
- 是未来自动生成（D）的对齐标准，也是护城河载体

## 四、模块切分（MECE）

第一版 6 个模块，覆盖公司全貌：

| 模块 | 诊断什么 | 典型工作方法 |
|---|---|---|
| 市场与客户 | 市场地位、竞争、客户、定价 | 假设驱动 |
| 产品与服务 | 产品力、组合、生命周期 | 框架扫描 |
| 营销与销售 | 获客、转化、渠道、销售效率 | 漏斗分析 |
| 运营与供应链 | 交付、成本、效率、瓶颈 | 流程建模 |
| 组织与人才 | 架构、人效、激励、文化 | 框架扫描 |
| 财务与资本 | 盈利、现金流、健康度 | 指标体检 |

策略：**全模块薄一层**——第一版先把 6 个模块的卡片都铺出来，把完整体验跑通，靠真实案例逐步加深每个 skill。

## 五、问卷形态

问卷替代自由对话，结构化但不死板。每个模块的问卷含两类问题：

1. **客观事实题**（喂给 skill 当数据）：营收、客户数、毛利率、竞品等；支持上传对应表格（销售流水、财务报表、花名册）
2. **主观痛点题**（帮 skill 定位）：老板自己觉得哪儿不对劲、最焦虑什么

**自适应追问**：根据老板的勾选动态追问（如勾"打不过竞品"→追问竞品是谁、价格带、丢单原因），把模糊焦虑逼成可分析输入。

## 六、结果卡片与下钻（产品的脸）

诊断完进入结果看板，6 模块各一张卡片，三层结构：

**第 0 层 · 看板总览**
- 每张卡顶部一个健康度信号（红/黄/绿 + 一句话结论）
- 例："🔴 营销与销售 — 获客成本翻倍，但转化没动，钱花在了错的渠道"

**第 1 层 · 卡片表层（结论先行）**
- 核心结论：问题是什么（1-2 句，So-What 直给）
- 关键证据：≤3 条，每条"数据 + 对比"（如"获客成本 ¥420，行业中位 ¥180，高 2.3 倍"）
- 建议行动：先动的 2-3 件事，按优先级

**第 2 层 · 查看更多（下钻）——只露事实，藏住方法**
- 数据依据：关键数据 + 来源 + 时间（内/外标注）
- 对比基准：你 vs 行业中位/标杆的数值对比、图表
- 结论与数据的关联：用**结果语言**陈述，不用方法语言

**两条硬规矩：**
- 表层永远不堆数据，只给结论 + ≤3 条关键证据
- 下钻里每个数据都要有"所以"，不允许"自己看图表"

## 七、护城河保护（核心商业要害）

矛盾：老板要"可信"（看得到证据），产品要"保密"（藏得住方法）。

**原则：只露"事实 + 结论"，藏住"方法 + 过程"。**
- **能露 = 结果性证据**：数据、对比、来源、结论（拿到这些也复现不出诊断）
- **必须藏 = 过程性方法**：框架、假设、分析链、为什么抓这些数据

**结果语言 vs 方法语言示例：**
- ❌ 泄密："我们假设问题在定价，于是抓竞品价格带做敏感性分析，发现……"
- ✅ 包装："你的定价高于 top3 竞品 18%，复购率低于行业 30%——价格是当前流失的主要因素。"

**工程层双保险：**
1. skill 指令、方法、prompt **永远服务端执行，绝不下发前端**；前端只收渲染好的结论和数据
2. 面向老板的文案**禁止出现方法论术语**（输出过滤：拦截/改写"假设""框架""敏感性分析"等词）

## 八、Skill 标准规范（护城河载体）

每个 skill 遵循统一契约，**只规定边界，不规定内部方法**：

```
skill 声明（元信息）：
  - 模块归属：市场/产品/营销/运营/组织/财务
  - 方法类型（自声明）：假设驱动/指标体检/框架扫描/流程建模…
  - 需要的输入：问卷哪些字段 + 哪些上传数据
  - 需要抓的外部数据：行业基准/竞品/政策…

skill 必须产出（强制契约 = 通用顾问原则）：
  - 结论先行的核心判断（So-What）
  - ≤3 条关键证据（数据 + 对比）
  - 2-3 条行动建议（按优先级）
  - 下钻包：数据 + 来源 + 对比（已按"只露事实"过滤）

skill 内部怎么干（自由且保密）：
  - 方法、框架、假设、分析链 —— 服务端执行，不外露
```

规范是地基：样板 skill 照它造，迭代加深对齐它，远期自动生成对齐它。

## 九、数据引擎（内外对比）

- **内部**：老板上传的表（销售流水、财务报表、花名册）→ 解析成结构化数据
- **外部**：skill 按需联网抓行业基准、竞品、市场大盘
- **对比层**：内部现状 vs 外部基准，算出差距（卡片上的"你 ¥420 / 行业 ¥180"）

## 十、技术形态与隐私

**第一版形态：Web 应用**（老板浏览器登录使用），问卷、看板、下钻都是天然网页交互。

**隐私两层：**
- **第一层（第一版做）**：传输 HTTPS 加密、上传数据加密存储 + 用完可自动删除、租户严格隔离。满足绝大多数客户。
- **第二层（远期）**：数据完全不出客户机器，需私有化/本地部署（B 形态）。

**关键决策：** 第一版做 A + 扎实的第一层隐私安全，架构预留私有化扩展位。B 不在第一版——因为本地部署会把 skill 暴露给客户，与护城河天然冲突；待真有客户硬性要求且配方保护方案成熟时再做。

## 十一、范围边界（YAGNI）

**第一版包含：**
- 6 模块自适应问卷
- 分诊编排中枢（最小可用）
- 6 个手工样板 skill（薄一层）
- 三层结果卡片 + 下钻（含护城河过滤）
- 内外数据对比引擎
- Web 应用 + 第一层隐私安全

**不在第一版（远期）：**
- skill 工厂（从网络知识自动生成 skill）—— 等标准和回路验证后再做
- 私有化/本地部署（B 形态）
- 方案陪跑/落地跟踪
